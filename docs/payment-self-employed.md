# Оплата для самозанятых: автообновление статуса заказа

Выжимка для **самозанятого без ИП**, который хочет, чтобы заказы в Ganesha сами переходили в статус `paid` после оплаты.

Связанные документы: [go-live.md §5](go-live.md#5-ручная-настройка-оплата-и-qr-сбер--сбп) · [backend.md § Оплата](backend.md#оплата)

---

## Главное

**Автообновление статуса возможно только через webhook** от платёжного сервиса.

Статический QR из СберБанка «Самозанятость» или перевод по СБП на карту/телефон **не шлют webhook** → Ganesha не узнаёт об оплате, заказ остаётся `pending_payment`.

---

## Что доступно самозанятому без ИП

| Способ | Статус `paid` сам? | Комментарий |
|---|---|---|
| QR / ссылка в «Самозанятость» (Сбер) | ❌ | Быстрый старт, ручная сверка в выписке |
| Перевод по СБП на телефон/карту | ❌ | То же |
| **ЮKassa** (агрегатор) | ✅ | Работает с самозанятыми без ИП |
| Эквайринг Сбера напрямую | ❌ | Нужен **ИП + расчётный счёт** |

**Вывод:** оставаясь самозанятым, путь к автоматике — **ЮKassa** (или другой агрегатор с webhook). Договор эквайринга в Сбере — только после регистрации **ИП на НПД**.

---

## Что уже есть в Ganesha

| Готово | Ещё нет |
|---|---|
| Приём webhook: `POST /api/payment/yookassa/webhook` | Создание платежа в ЮKassa при оформлении заказа |
| После webhook → `paid`, уведомления клиенту | Кнопка «Оплатить» вместо статического QR на странице оплаты |
| Поддержка групповой оплаты (`payment_group_uuid`) в `PaymentService` | |

Сейчас на `/order/{uuid}/pay` показывается **статический QR** из `.env` (`PAYMENT_QR_URL`). Клиент переводит сам — система об оплате **не узнаёт**.

Для end-to-end нужна доработка: **создать платёж в ЮKassa → показать ссылку «Оплатить» → webhook обновляет статус**.

---

## Рекомендуемый план (самозанятый + ЮKassa)

### Шаг 1. Регистрация в ЮKassa (~1–3 дня)

1. Зарегистрироваться на [yookassa.ru](https://yookassa.ru) как **самозанятый** (ИНН + приложение «Мой налог»).
2. Включить **авточеки** в «Мой налог» через ЮKassa.
3. В личном кабинете получить **shopId** и **secret key**.

### Шаг 2. Webhook

В настройках ЮKassa:

| Параметр | Значение |
|---|---|
| URL | `https://ваш-домен.ru/api/payment/yookassa/webhook` |
| Событие | `payment.succeeded` |
| Заголовок | `X-Yookassa-Secret: <ваш_секрет>` |

В `.env.local` на сервере:

```dotenv
YOOKASSA_WEBHOOK_SECRET=ваш_секрет
DEFAULT_URI=https://ваш-домен.ru
```

**HTTPS обязателен** — без него webhook не примут.

### Шаг 3. Metadata для Ganesha

При создании платежа в API ЮKassa в `metadata` передавайте:

| Тип заказа | Поле `metadata` |
|---|---|
| Один день | `order_uuid` = UUID заказа |
| Несколько дней (группа) | `order_uuid` = `payment_group_uuid` с страницы оплаты |

Адаптер читает `metadata.order_uuid`; `PaymentService` сам найдёт группу по `payment_group_uuid`.

### Шаг 4. Доработка Ganesha (разработка)

На странице оплаты вместо статического QR:

1. Создать платёж в ЮKassa на сумму заказа (или группы).
2. Показать кнопку **«Оплатить»** → страница ЮKassa (карта / СБП).
3. После оплаты webhook → статус `paid` без ручных действий.

## Комиссии и налоги (ориентир)

| | |
|---|---|
| **Комиссия ЮKassa** | ~2,8–3,5% по карте, ~0,4–0,7% по СБП (зависит от тарифа) |
| **НПД** | 4% от физлиц, 6% от юрлиц |
| **Важно** | Налог считается с **полной суммы** от клиента, не «после комиссии» |
| **Чеки** | На каждый платёж — через «Мой налог» (у ЮKassa часто автоматически) |

## Альтернатива: ИП на НПД + Сбер

Если нужен именно Сбер:

1. Зарегистрировать **ИП на НПД** (налог как у самозанятого, лимит **2,4 млн ₽/год**).
2. Открыть **расчётный счёт**, заключить договор **интернет-эквайринга**.
3. Webhook: `POST /api/payment/sber/webhook`, секрет `SBER_WEBHOOK_SECRET`.
4. В `orderNumber` передавать `order.uuid` или `payment_group_uuid`.

И здесь нужна **та же доработка** — создание платежа через API Сбера, а не статический QR.

Подробнее про Сбер: [go-live.md §5.3](go-live.md#53-режим-b--webhook-сбербанка).

## Временный обход (без автоматики)

Пока нет ЮKassa — **режим A** из [go-live.md](go-live.md):

- статический QR + `PAYMENT_CARD` в `.env`;
- сверка поступлений в банке;
- ручное подтверждение через `POST /api/payment/webhook` (curl).

Подходит для пилота с малым потоком, но **не масштабируется**.

---

## Чего не делать

- ❌ Не ждать автообновления от статического QR Сбера «Самозанятость».
- ❌ Не ждать webhook от обычного перевода на карту/телефон.
- ❌ Не подключать эквайринг Сбера, оставаясь самозанятым без ИП — не оформят.
