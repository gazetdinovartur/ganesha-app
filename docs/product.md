# Продукт (MVP)

Система приёма заказов на **регулярное вегетарианское питание** с самовывозом в центре йоги «Хануман» (Екатеринбург).

**Не в MVP:** событийный кейтеринг (ретриты) — ведётся вручную, без экранов в админке.

---

## Каналы

| Канал | Роль |
|---|---|
| Сайт | Основной UX: меню, корзина, оплата, статус |
| Telegram-бот | Дублирует сайт |
| VK-бот | Дублирует сайт |

## Бизнес-правила

| Параметр | Значение |
|---|---|
| Горизонт меню | до **7 дней** |
| Публикация | только `MenuDay.isPublished = true` |
| Cutoff | заказ на день **D** до **18:00** дня **D−1** (`Asia/Yekaterinburg`) |
| Самовывоз | `PickupPoint` (MVP: Хануман, Щорса 37А) |
| Телефон на сайте | **обязателен** |
| Согласие на ПДн | **обязательно** перед первым заказом (сайт, TG, VK) |
| Оплата | QR / СБП → **автоподтверждение через API провайдера** |
| Email клиенту | нет |

---

## Статусы заказа

| Код | Клиент видит | Когда |
|---|---|---|
| `pending_payment` | Ожидает оплаты | После оформления |
| `paid` | Заказ принят, готовим | Webhook от платёжного API |
| `ready` | Можно забирать | Коробка в Ханумане |
| `completed` | Спасибо | Выдан / день закрыт |
| `cancelled` | Отменён | До cutoff или вручную |

Поле `paidAt` выставляется автоматически при переходе в `paid`.

---

## Оплата (без лишних кнопок)

1. Клиент оформляет заказ → `pending_payment`.
2. Видит QR / реквизиты; в комментарии к переводу — **идентификатор заказа** (`uuid` или `humanNumber`, по договорённости с провайдером).
3. Платёжный провайдер (банк, СБП, агрегатор) при успехе вызывает **наш webhook** → заказ `paid` + `paidAt`.
4. Клиент видит обновление на странице статуса / в боте.

**Нет:** кнопки «Я оплатил», ручного подтверждения в админке.

Подробнее API: [backend.md — Оплата](backend.md#оплата).
